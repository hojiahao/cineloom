# 十日谈：一台 DGX Spark，一支广告片

方舟团队 · 第三届 NVIDIA DGX Spark 黑客松 · Agent Skills 开发挑战赛

项目仓库：https://github.com/hojiahao/cineloom

## 起点

报名时我们只有一个想法：让一台放在桌上的机器，把“给某个产品做条 15 秒广告”这句话，直接变成一支能看的片子。

现在的 AI 视频工具已经能出不错的画面，但真拿来做广告，有几件事让人不放心。新品还没发布，素材不敢往云上传。一个镜头不满意就得重新生成，每次都要花钱。还有就是没人把关，片子做完才发现文案里写了“全网第一”，或者产品上的字被画歪了。

DGX Spark 有 121.7 GB 统一内存。我们粗算了一下，写文案的语言模型、看图的视觉模型、生图和生视频的模型，可以挤在同一台机器上。那就试试把整条流程都放进去。

## 做成了什么

最后的作品叫 CineLoom，中文名影织。在网页上输入一句创意，它会依次写需求、写脚本、审合规、画分镜、出图、质检、生成视频、剪成片，交出一支带配音、配乐和字幕的短片，外加一份交付报告，写明每个镜头被退回过几次、原因是什么。

撑起这套流程的是我们自己写的运行时 CineLoom Harness。八个环节的顺序写在代码里，每个环节交给一个子智能体，每个子智能体加载一份对应的 Agent Skill，也就是写给模型看的专业手册，比如广告脚本怎么分拍，分镜怎么写视频模型才看得懂。子智能体交上来的东西先过一段校验程序，不合格就带着具体问题退回重写。我们后来的说法是：顺序和验收交给代码，判断交给模型。

模型都是一个个试出来的。写文案用 NVIDIA 的 Nemotron 3.5 Lightning，配上官方为 DGX Spark 调好的投机解码，本机每秒一百个 token 左右。看图质检用阶跃星辰的 Step3-VL。图片和视频交给 Qwen-Image 与 Wan2.2，配乐用 ACE-Step，都在本机的 ComfyUI 里跑。配音先用了阶跃的 Step-Audio-EditX，最后换成 Qwen3-TTS 按文字描述设计出来的旁白音色。

十天里一共做了四支样片：气泡水“冷”、机械键盘“青”、面霜“润”、挂耳咖啡“醒”。品牌都是虚构的。

## 几件印象深的事

第一支片子出来，罐子在第一个镜头是铝罐，第二个镜头成了瓶子。每个镜头是单独生成的，模型不记得上一个镜头画了什么。后来我们先生成一张产品定妆照，让看图的模型确认没问题，之后每一帧都拿它当参考图。从那以后，一支片子里就一直是同一只罐子。

画面里的字也吃过亏。图像模型会把提示词里的“50mm”画成画面上的字，还会把“泠”写成“冷”。于是我们不再让它写任何字，标题和字幕都放到后期用真字体排，排之前先检查字体里有没有这几个字。

面霜那支让我们很意外。负责分镜的智能体把 Skill 文档里举例用的气泡水，原样抄进了面霜的分镜。质检连着三次指出“标签上是冷，不是润”，系统还是带着错的产品把片子做完了。那天改了三处：分镜里必须写出这支片子自己的品牌字，定妆照三次不过就停，Skill 里的示例改成没法照抄的写法。过了两天，写脚本的智能体又把示例里的标题“开罐”用到了挂耳咖啡上，于是又加了一条：标题里提到的容器，得是这个产品真有的。

最难的是机械键盘，前后做了五版。第一版三个镜头几乎一个角度，键帽上的字母全是乱码，底下还亮着没人要的彩虹灯。之后每一版修掉旧问题，又冒出新问题：有一版每个镜头都有手，有一版键盘在定妆照里被竖了起来，还有一版因为分镜里写了“黄铜质感”，键盘直接变成了金色。我们没有换模型，而是去看真实的数码产品广告怎么拍：暗背景，一两种冷色光，手最多出现一次，键帽小字用浅景深虚掉。这些都写进了分镜 Skill，能自动检查的写进了校验程序。到第五版才算满意。

## 提速：试了三条路，成了一条

一支 15 秒的片子在本机要做三四十分钟，我们一直想让它快一点。

第一个猜测是内存不够用。两个语言模型常驻，占掉将近一半内存，我们以为视频模型每生成一段都要重新搬一次权重。于是让语言模型在生成视频时进入 vLLM 的睡眠模式，可用内存从 47 GB 涨到 104 GB。结果视频每段还是 340 秒左右，一秒没少，语言模型反而慢了十倍。这条路走不通，退回来了。

第二个猜测是质检太慢。看图的模型每次要先推理一千多个 token 才下结论，一张图要一分多钟。我们试过让它跳过推理直接打分，3 秒就能出结果，可它开始把合格的图判成不合格，给的理由也对不上画面。质检不准比质检慢更糟，这条也放弃了。

真正起作用的是几处小改动：首帧按视频的实际尺寸出图，不再生成更大的图；第二个候选只在第一个被退回时才生成；送审的图先缩小；审这一张的同时，下一张已经在生成。首帧这一段从 1141 秒降到了 524 秒，整支片子最快 1842 秒，比原来少了 18%。视频那一段每段 340 秒左右，是 14B 模型在 720p 下实打实的计算，不降画质就省不下来。两条失败的尝试，我们也都写进了 README。

## 数字

我们用同一个 Nemotron、同一批 8 个创意、每个跑 2 轮，只改一个变量：子智能体有没有加载 Skill，每个环节只给一次机会。第一次测的时候，没有 Skill 的分镜一次都没合格过（0/16），加上 Skill 后是 8/14，平均违规从 8 条降到 0.71 条。后来我们把节拍数、字数这些硬性要求直接写进了提示词，没有 Skill 的那一组也跟着变好了，第三次测试时脚本合格从 11/16 到 14/16，分镜从 0/15 到 6/15。三次结果都留在了仓库里。我们得出的结论是：能写成硬规则的，就直接写进提示词；需要判断的，才留给 Skill。分镜正是判断最多的环节，差距也最明显。

四支样片在本机分别用了 2256 秒（气泡水）、2432 秒（键盘第五版）、4564 秒（面霜，和另一个任务同时跑）和 3645 秒（咖啡）。

## 还没做完的

视频这一段还没有找到不降画质的提速办法。一个镜头返工两次，就能把前面省下的时间吃回去，下一步想让分镜少写模型画不出来的东西。音效也还没加。

十天里，每一次翻车最后都变成了 Skill 里的一句话，或者校验程序里的一行代码。回头看，这大概就是 Agent Skills 对我们最实在的用处：经验能写下来，能拿来测，也能留给下一个智能体。
