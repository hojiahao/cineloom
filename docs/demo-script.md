# 演示视频脚本（B 站提交用，目标 4–5 分钟）

两种做法，二选一或叠加：

1. **自动版**：`python3 scripts/demo-reel.py --out ~/cineloom-demo/cineloom-demo.mp4` 从仓库自己的产物（运行记录、被拒与通过的首帧、四支成片、消融结果）生成一支约 3.5 分钟的成片，卡片用 Pillow 画、旁白用本机 TTS 合成、数字全部从 `eval/results` 与 `projects/*/reports` 读取。成片变了就重跑一次。
2. **人工版**：屏幕录制 Studio 与终端，穿插成片片段，旁白按下面的文字念或作为字幕。

所有数字均为本机实测，不得改动。

## 0:00–0:30 痛点

画面：三张截图——云端视频工具的上传界面、按条计费页、一张产品在两个镜头间变样的对比图（用 `leng-soda` 第一版）。
旁白：做一条短视频广告要经过策划、文案、分镜、生成、剪辑。现有工具把这些放在云端：未发布新品的素材不能上传；一个镜头重生成五次是常态，按次计费劝退；生成结果没人把关，一句“全网第一”、一个变形的 logo，到成片才发现。

## 0:30–1:10 一句话开拍

画面：打开 Studio，输入创意“给一款叫‘冷’的无糖气泡水做一条 15 秒竖版广告，面向大学生，夏天”，点“开拍”。运行日志逐行出现。
旁白：CineLoom 跑在一台 DGX Spark 上。你说一句创意，CineLoom Harness 按八个阶段推进，每个阶段是一个加载了 Skill 的子智能体。代码管顺序和验收，模型管判断。

## 1:10–2:10 先审后生成

画面：日志停在“脚本 第 1 稿被校验器退回”，展示退回原因；然后合规阶段的独立审稿；再切到分镜 JSON 与 Jev 的判定概率。
旁白：文案先过《广告法》用词扫描和一个没写这份稿的审稿智能体，有问题的文案到不了生成环节。分镜里每个镜头只允许一个运镜、不允许让模型画字，违反就退回重写——这些规则来自失败：我们实测模型把“50mm”画进了画面，把“泠”画成了“冷”。

## 2:10–3:10 定妆图与质检闭环

画面：定妆图生成 → 质检通过；首帧两个候选，一个被拒（原因文字），另一个通过；三个镜头首帧并排，罐子一致。
旁白：产品先出一张过质检的定妆图，之后每一帧都从它生成，所以整支片子里是同一只罐。每一帧由 StepFun 的视觉模型对照定妆图复核，不合格就改提示词重生成，把返工拦在 20 秒的生图阶段，而不是 6 分钟的生视频阶段。

## 3:10–3:50 成片

画面：播放气泡水成片（有声）；再切键盘横版、面霜竖版各 5 秒。
旁白：视频由 Wan2.2 14B 在本机生成，配音和音乐也在本机；标题字幕用真字体后期排版。这三支分别是饮料、数码、护肤，竖版和横版。

## 3:50–4:30 证据

画面：README 的实测表；BENCHMARK 对比表（带 / 不带 Skill）；`cineloom mem status` 输出。
旁白：一支 15 秒成片在这台机器上约 38 到 60 分钟，全程本地。同一个模型、同一批创意，不带 Skill 时分镜一次合格 0/15，带 Skill 后 6/15；每条规则都对应一次真实的翻车。

## 4:30–4:50 收尾

画面：架构图；仓库地址。
旁白：CineLoom，影织。把一句创意，织成一支成片。
